# 复刻目标：dsh-tauri 功能全集

- 版本：v0.1
- 日期：2026-10-20
- 基线：`dsh-tauri/deepseek-harness-desktop` v0.24.5；推荐核心 `0.2.1-rc.2`，最低 `0.1.7-rc.1`
- 目标：**功能上全量对齐 dsh-tauri 桌面端**，用 Rust + GPUI 原生实现；不追求像素级一致，
  但关键流程、状态与数据行为必须一致。
- 边界：
  - 不重写 dsh 内核、不复用 Tauri/React 代码与 UI 资产；
  - **移动端 App（Android/iOS）是否复刻待定**（见 §6）；
  - dsh-tauri 为 MIT + Non-Commercial 条款，宠物素材/图标等资产需单独确认授权。

> 这份清单取代 OUTLINE 里"MVP 子集"的旧范围。分期实现，但**目标不是子集**。

## 2. 与既有决策的冲突

以下旧决策是"MVP 子集"思路下的产物，与"完全复刻"冲突，需要重新拍板：

| 旧决策 | 新目标 | 建议 |
| --- | --- | --- |
| 只 attach 外部 dsh，不内嵌 | dsh-tauri 自己下载并管理 Node/dsh、可切核心 | 改为**默认管理式运行时 + 可选 attach**；M0 的 attach 作为过渡与调试入口保留 |
| 不做远程/局域网 | LAN 共享、QR、Cloudflare 隧道 | 桌面端远程能力纳入 P3；移动 App 待定 |
| 不做终端、不做文件编辑 | 侧栏有终端；文件为只读预览 | 终端 P2；文件编辑 dsh 本身无写 API，保持只读 |
| 插件只做启停 | 内置 12 插件、preset、市场、依赖、HMR | 插件完整管理 P2 |
| 首版仅 macOS | 三平台（Win/mac/Linux） | macOS 先行，P4 跨平台 |
| MVP 不做宠物/个性化 | 宠物、8 调色板、模糊、缩放等 | P3，按优先级取舍 |
| 不做远程鉴权 | LAN/隧道需要访问码/配对 | 随 F1 一起设计 |

**不变**：不与官方 Web UI 竞争、不重写 dsh 内核、不做像素级 UI 复刻。

## 4. 复刻验收方式

1. **功能对照表**：本文件每一项打勾，标注"一致 / 简化 / 不做"及原因。
2. **并排演示**：同一台机器、同一 `$DSH_HOME`，dsh-tauri 与 dshg 跑同一会话、同一插件、同一核心，
   对比关键流程（审批、终端、切核心、插件安装）。
3. **数据兼容**：dshg 与 dsh-tauri/`dsh` 共用 `$DSH_HOME`，切换客户端不丢会话/设置/凭据。
4. **回归清单**：安装→配置→日常使用→升级→卸载。

## 5. 主要风险

- **范围**：这是一个完整桌面产品，不是客户端壳；P0–P2 的工作量已远超此前估算。
- **运行时管理**：下载/校验/解压/多版本/回滚，平台差异大（Windows ACL、Linux 库依赖）。
- **宠物/视频**：GPUI 对视频/透明窗体的支持需验证；素材授权需单独确认。
- **远程/隧道**：QR 配对、访问码、Cloudflare 隧道、SSH 同步，安全模型复杂。
- **插件生态**：内置插件是 TS 插件，dshg 只做管理面（安装/启停/配置），不重写插件运行。
- **更新器**：GPUI 无现成 Tauri updater，需要自建签名更新流程。
- **平台**：GPUI Kit 的 Linux/Windows 成熟度未知，P4 前需实测。
